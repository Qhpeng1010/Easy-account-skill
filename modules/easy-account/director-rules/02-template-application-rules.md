# 易账通模板与应用规则

## 页面家族地图

**EA-TPL-001** 当主要任务是查找、比较或处理一组账户或账务记录时，使用查询列表家族；创建、编辑、开户或调账一个业务对象时，使用表单家族；只读查看时，使用详情家族；结果页只用于已知来源操作的反馈；只有主要任务是监控有明确时间范围和口径的业务健康度、分布或趋势时，才使用 Dashboard。

**EA-TPL-002** 空数据、错误、无权限和缺少前置条件通常是所属页面家族的状态，不能取代原本应有的页面家族。每个页面只能选择一个主页面家族，浮层和结果跳转只能服务于该主家族。

## 查询列表选择与组合

**EA-TPL-003** 查询字段不超过 6 个且相互独立时，使用普通查询列表；字段超过 6 个、筛选有条件依赖或需分组时，使用高级查询列表。普通查询列表的条件超过 3 个时必须提供展开/收起；默认展示全部条件，收起后展示前 3 个条件。高级查询必须受当前策略与已验证组合约束，不能仅因规则存在而直接生成。

**EA-TPL-004** 常规列表严格由一个查询任务模块和一个结果任务模块组成，两者是直接同级、间距 `16px`。查询列表默认直接从查询条件区开始，不渲染面包屑、页面标题、标题说明或其他页面级冗余内容。当业务分类决定不同的查询字段或查询口径时，Ant Design Tabs 必须位于查询任务模块最顶部，与查询条件属于同一个白色业务面；切换 Tabs 后在其下方展示当前分类对应的查询条件，结果任务保持标准列表标题和标准 Table，不得在 Table 顶部重复分类 Tabs。当业务分类只切换同一查询口径下的数据集、查询字段不变时，Tabs 才可在结果任务中替代列表标题，Tabs 与列表标题不可同时出现。查询条件由标签和 Ant Design 控件组成；重置、查询和展开/收起位于查询任务内的最后一列，按钮组右对齐，且与当前行控件底边对齐，按钮间距固定为 `8px`。条件超过 3 个时，默认全量展示并显示“收起”按钮；收起后显示“展开”按钮，展开/收起位于重置、查询之后，是按钮组最右侧控件，文字在左、icon 在右。展开/收起文字按钮的左内边距固定为 `8px`，右内边距为 `0`，不保留 Ant Design 文字按钮默认的 `15px` 右内边距。结果任务内的 Table 顶部默认只保留一个列表标题，不展示标题说明、结果摘要或重复记录数。无论是标准列表标题还是结果分类 Tabs 形态，结果工具栏整体高度都必须限定为 `32px`，右侧全局操作按钮也必须限定为 `32px` 高；标题或 Tabs、按钮组必须位于同一水平行并垂直居中对齐，且切换标题形态不得改变工具栏高度。每个标准 Table 都必须在结果工具栏右侧提供列设置，使用仅图标按钮并具备“列设置”可访问名称；列设置只控制可隐藏业务列，不允许隐藏操作列。工具栏、表格与分页必须留在结果任务内。统计只属于结果模块内部，不能独立成为第三块业务卡片。Table 的状态列必须使用 Ant Design Tag 展示，Tag 同时包含明确的中文状态文案和对应语义色；不得使用 Badge、单独圆点或仅改变文字颜色表示状态。

**EA-TPL-005** 列表新增、编辑或详情只有在关闭后需要保留不变的筛选、分页、滚动和选择上下文时，才可使用 Modal 或 Drawer。列表详情仅适用于边界清晰的只读信息；复杂流程、大量关联记录、操作日志或长表格应打开独立详情页。

### 结果 Tabs 与操作列补充规则

- 结果区使用分类 Tabs 时，保留 Ant Design Tabs 默认导航高度，在工具栏上方增加 `8px` 空间并保留默认底部 `16px` 间距，使 Tabs 区块总高度为 `70px`。
- 结果区分类 Tabs 隐藏导航底部的灰色分割线，只保留选中态品牌色底边。
- 操作列宽度按实际操作数量设置，应完整容纳“查看、编辑、渠道绑定”，避免右侧大面积空白。
- 标准列表标题默认使用“查询列表”；只有用户明确给出其他标题时才替换。
- Table 的列标题和字段值必须完整可见，字段较长时按当前列宽折行；不得以省略号截断业务字段。操作列与状态 Tag 等紧凑控件可保持单行。

## 表单选择

**EA-TPL-006** 从列表、详情或当前任务内发起，字段少且相互独立、可一次提交完成时，使用 Modal 表单。弹窗内的字段与分组必须服务于明确业务语义，不得为了填充空白创建无业务含义的分组、摘要或装饰模块。复杂联动、长校验、上传、多个业务分区或不可逆提交不能压缩在 Modal 中。

**EA-TPL-007** 新增或编辑任务在 Drawer 与整页表单之间选择时，用户需录入、选择或上传的信息项不超过 8 项，且任务可在单一连续上下文内完成时，使用 Drawer；信息项超过 10 项时，必须使用整页分组表单。信息项为 9–10 项时作为过渡区：单一业务模块、无复杂联动、上传或长说明且需要保留来源上下文时使用 Drawer；包含多个需分别核对的业务模块、复杂联动、上传或长说明时使用整页分组表单。只有后续工作依赖前一步完成，或存在上传、解析、复核与提交等明确阶段时，才使用步骤表单。分组表单不得叠加右侧说明配图或第二个主表单；步骤表单不得与 Modal 表单组合。

## 详情、结果与概览选择

**EA-TPL-008** 详情按身份、账户状态、余额口径、关联记录和操作日志分组呈现。金额摘要不得脱离币种、口径和时间范围单独展示；可变更账务的动作必须使用明确操作，不得隐藏在普通文本链接中。结果页必须说明影响对象、金额、币种、业务单号和恢复路径，且不得作为独立业务入口。

**EA-TPL-009** Dashboard 只服务跨记录的业务监控，必须有统一数据范围和口径，并至少包含核心指标、分布或趋势等能够支持判断的视图；不能混入查询结果表格、分页、行操作或批量操作。需要逐条查询、核对或处理记录时，改用查询列表。

## 页面组合约束

**EA-TPL-010** 详情页不得把所有字段渲染成可编辑控件。表单的返回、取消和关闭均需遵循未保存修改确认；辅助浮层不可承载完整步骤流程，也不得替代来源页面本身。

## 能力边界与选择证据

**EA-TPL-011** 当前策略决定哪些页面家族、能力和组合可以生成。`shadow` 页面必须引用同页面族且能力集合匹配的已验证组合；`workflow-only`、`legacy` 或 `pending` 页面不能通过 Page Spec 直接生成，必须报告能力缺口。

**EA-TPL-012** `page-design.md` 和 Page Spec 元数据必须记录已选页面家族、页面方案、能力证据、被排除方案、假设和运行模式。没有策略与验证证据，不得构建或交付。

**EA-TPL-013** “多个业务模块”指表单需要按两个及以上独立业务语义分区，例如业务主体、主体信息、法人信息和结算信息；“信息项”只统计需要用户录入、选择或上传的可交互字段，纯展示说明、模块标题和系统自动回填字段不计入。按照 `EA-TPL-007` 命中整页条件后选择 `form.page`，不得继续使用 Modal 或 Drawer 承载。整页分组表单由一个独立通栏标题模块、一个主表单、按业务语义拆分的同级信息模块和一个固定底部操作区组成；标题模块位于所有信息模块之前，承载返回入口和唯一页面标题，不得并入第一个信息模块。信息模块顺序遵循前置选择、主体信息、补充信息和提交确认的任务依赖，不得按控件类型机械分组。

**EA-TPL-014** 内容工作区外层在 Shell 内统一使用 `12px` 内边距；页面内容区的标题、查询、结果和表单分组等直接同级业务模块内边距统一为 `16px`，并统一使用 `8px` 圆角，相邻模块的垂直间距统一为 `16px`。不得通过额外空白、嵌套卡片或不同圆角制造层级。整页新增表单的操作区必须固定在内容视口底部并在页面滚动时始终可见，横向覆盖内容工作区，使用白色背景，顶部以浅色阴影区分表单内容。操作按钮右对齐，次操作在左、主操作在右，按钮间距为 `8px`；每个按钮宽度按文字、图标和水平内边距自适应，不设置等分宽度，不使用 `flex: 1`，也不得随操作区宽度自动撑满。

**EA-TPL-015** 整页新增表单包含超过 10 个可交互信息项时，各业务信息模块仍按任务顺序纵向排列，但模块内部必须使用标签在上、控件在下的垂直表单布局，不得使用标签在左、控件在右的水平表单布局。普通输入、选择、日期和金额等短字段使用 24 栅格排列：内容工作区宽度不小于 `1200px` 时每项占 `8/24`、每行 3 项；`768px-1199px` 时每项占 `12/24`、每行 2 项；小于 `768px` 时每项占 `24/24`、每行 1 项。控件填满所属栅格列，同行标签基线和控件顶部对齐。地址、上传、长说明、富文本、复杂联动及需要完整帮助或校验信息的字段可按内容需要占 `16/24` 或 `24/24`，不得为了凑满三列压缩可读性；隐藏或条件字段出现、消失后按原字段顺序重新排布，不保留无意义空列。
