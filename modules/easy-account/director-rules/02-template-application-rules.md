# 易账通模板与应用规则

## 页面家族地图

**EA-TPL-001** 当主要任务是查找、比较或处理一组账户或账务记录时，使用查询列表家族；创建、编辑、开户或调账一个业务对象时，使用表单家族；只读查看时，使用详情家族；结果页只用于已知来源操作的反馈；只有主要任务是监控有明确时间范围和口径的业务健康度、分布或趋势时，才使用 Dashboard。

**EA-TPL-002** 空数据、错误、无权限和缺少前置条件通常是所属页面家族的状态，不能取代原本应有的页面家族。每个页面只能选择一个主页面家族，浮层和结果跳转只能服务于该主家族。

修改已有页面时，用户明确要求保留现有入口、Modal、Drawer 或整页结构的，以现有结构为基线；新建任务的字段数量阈值不触发结构迁移。Page Spec 使用 `preserveStructure: true` 记录该约束，仍须满足视口高度、内容滚动、标题和操作区规则。

## 查询列表选择与组合

**EA-TPL-003** 查询字段不超过 6 个且相互独立时，使用普通查询列表；字段超过 6 个、筛选有条件依赖或需分组时，使用高级查询列表。普通查询列表的条件超过 3 个时必须提供展开/收起；默认展示全部条件，收起后展示前 3 个条件。高级查询必须受当前策略与已验证组合约束，不能仅因规则存在而直接生成。

**EA-TPL-004** 常规列表由一个查询任务模块和一个结果任务模块组成。声明 `summary` 且汇总指标不超过 3 条时，汇总替换结果任务的查询列表标题，不增加中间区域；超过 3 条时，在查询与结果任务之间增加一行无外层业务面的查询结果统计卡片。存在卡片行时，查询模块、统计卡片行和结果模块之间的垂直间距固定为 `16px`。查询列表默认直接从查询条件区开始，不渲染面包屑、页面标题、标题说明或其他页面级冗余内容。

当业务分类决定不同的查询字段或查询口径时，Ant Design Tabs 必须位于查询任务模块最顶部，与查询条件属于同一个白色业务面；顶层业务 Tabs 的导航区域必须横向铺满业务模块并统一使用 `#FBFCFC` 浅灰背景，导航区域底部使用 `1px solid #E4E4E7` 分割线，选中态仍使用品牌色文字和底边。切换 Tabs 后在其下方展示当前分类对应的查询条件，结果任务保持标准列表标题和标准 Table，不得在 Table 顶部重复分类 Tabs。当业务分类只切换同一查询口径下的数据集、查询字段不变时，Tabs 才可在结果任务中替代列表标题，Tabs 与列表标题不可同时出现。

查询条件由标签和 Ant Design 控件组成；重置、查询和展开/收起位于查询任务内的最后一列，按钮组右对齐，且与当前行控件底边对齐，按钮间距固定为 `8px`。条件超过 3 个时，默认全量展示并显示“收起”按钮；收起后显示“展开”按钮，展开/收起位于重置、查询之后，是按钮组最右侧控件，文字在左、icon 在右。展开/收起文字按钮的左内边距固定为 `8px`，右内边距为 `0`，不保留 Ant Design 文字按钮默认的 `15px` 右内边距。

结果任务内的 Table 顶部默认只保留一个列表标题；存在 1–3 条查询汇总时，由紧凑查询汇总替换列表标题，不再重复显示标题、结果摘要或记录数。无论是标准列表标题、紧凑查询汇总还是结果分类 Tabs 形态，结果工具栏右侧全局操作按钮都必须限定为 `32px` 高；左侧内容与按钮组位于同一水平行并垂直居中，空间不足时紧凑查询汇总可自然折行但不得截断、重叠或挤走右侧操作。每个标准 Table 都必须在结果工具栏右侧提供列设置，使用仅图标按钮并具备“列设置”可访问名称；列设置只控制可隐藏业务列，不允许隐藏操作列。工具栏、表格与分页必须留在结果任务内。

统计必须先按业务语义分为对象总览与查询结果汇总，不能使用一个通用统计区混用两种口径。对象总览使用 `overview` 区域，只说明当前选中企业、账户或其他主对象，与主对象选择器、查询条件共同位于查询任务模块，顺序固定为“分类 Tabs、主对象选择器、对象总览、查询条件”，并使用 Ant Design `Statistic`；这类组合查询不再为查询条件额外渲染“流水查询”“查询条件”等小标题。多 Tab 查询只有部分分类需要对象总览时，Page Spec 使用 `overview.config.visibleTabKeys` 声明显示总览的查询 Tab key；数组必须非空、唯一且全部引用已声明的查询 Tab。未声明该配置时，总览在全部 Tab 展示。未命中的 Tab 只渲染普通查询列表，不显示总览、总览管理入口或总览专属间距，并且选择器保持纵向布局。仅在主对象选择器后紧接可见对象总览的组合中，选择器使用标签在左、控件在右的横向表单布局；桌面端选择器整体宽度与下方对象总览的第一个 `Statistic` 指标列一致，不得继续占用更宽的固定列；小于 `768px` 时恢复整行纵向布局。普通查询条件和不带可见对象总览的选择器继续使用标签在上、控件在下的纵向布局。主对象选择器与对象总览之间不使用分割线；对象总览与其后紧接的查询条件之间增加 `1px solid #EDEDED` 的灰色分割线；对象总览标题上方固定保留 `32px` 间距。

查询结果汇总使用 `summary` 区域，只描述当前查询结果的数量、金额或其他聚合口径；不得移动到查询条件上方，也不得使用主对象选择器的即时总览数据冒充查询结果。汇总值随查询、重置和分类切换后的结果集更新。汇总指标为 1–3 条时，替换查询列表标题并使用 `14px / 22px` 文字，严格按“查询汇总：标题 数值 单位｜标题 数值 单位｜标题 数值 单位”组织；“查询汇总：”、标题、单位使用正文色，数值使用主色 `#1E75FF`，分隔符使用全角 `｜` 且颜色固定为 `#E4E4E7`，不使用 Ant Design `Statistic` 卡片。汇总指标超过 3 条时，固定渲染在查询条件模块下方、结果 Table 上方，不显示可见标题，不渲染外层业务模块，只保留独立的 Ant Design `Statistic` 统计卡片；卡片间距为 `12px`，内边距为 `16px`，使用 `6px` 圆角、白色背景且无边框、无阴影。同一页面同时需要对象总览和查询结果汇总时，顺序按汇总数量分别为“主对象选择器、对象总览、查询条件、结果工具栏内查询汇总、结果 Table”或“主对象选择器、对象总览、查询条件、统计卡片、结果 Table”。

对象总览存在与当前对象直接相关的独立管理任务时，Page Spec 显式声明 `overview.manage` 并提供管理配置后，默认在总览标题行右侧渲染一个 `32px` 高的管理按钮；只有具体配置明确声明 `visible: false` 时才隐藏，不把领域管理入口擅自添加到没有该能力的总览。该管理入口默认使用 Primary，只有具体 Page Spec 明确声明 `primary: false` 时才降级为次级按钮。管理入口打开 Ant Design Modal，新建任务默认最多承载 6 个可交互字段；修改已有页面并明确要求保留 Modal 时声明 `preserveStructure: true`，可继续使用原结构并让超高内容区独立滚动。字段、选项、校验、初始值、提交文案和成功反馈均由具体产品或业务 Page Spec 定义，共享规则不得写死某类规则字段。按钮与弹窗只服务当前总览对象，不得移入查询结果汇总或结果 Table 工具栏。

对象总览内部的统计项保持平铺，相邻统计项之间使用居中的 `1px` 宽、`16px` 高竖向分隔线，颜色为 `#E4E4E7`；指标在小屏堆叠为单列时隐藏竖线。当总览后紧接查询条件时，仍仅在总览与查询条件之间显示上述 `#EDEDED` 分割线。超过 3 条的查询结果汇总不形成外层业务模块，只通过 `16px` 灰色间距与查询条件和结果 Table 分隔，并按上一条规则直接展示无边框圆角统计卡片。顶层业务 Tabs 的导航底部仍保留业务分割线，结果 Table 的外边框按表格规则保留。

Table 的状态列必须使用 Ant Design Tag 展示，Tag 同时包含明确的中文状态文案和对应语义色；不得使用 Badge、单独圆点或仅改变文字颜色表示状态。

**EA-TPL-005** 列表新增、编辑或详情只有在关闭后需要保留不变的筛选、分页、滚动和选择上下文时，才可使用 Modal 或 Drawer。列表详情仅适用于边界清晰的只读信息；复杂流程、大量关联记录、操作日志或长表格应打开独立详情页。

### 结果 Tabs 与操作列补充规则

- 结果区使用分类 Tabs 时，保留 Ant Design Tabs 默认导航高度，在工具栏上方增加 `8px` 空间并保留默认底部 `16px` 间距，使 Tabs 区块总高度为 `70px`。
- 结果区分类 Tabs 隐藏导航底部的灰色分割线，只保留选中态品牌色底边。
- 操作列宽度按实际操作数量设置，应完整容纳“查看、编辑、渠道绑定”，避免右侧大面积空白。
- 标准列表标题默认使用“查询列表”；只有用户明确给出其他标题时才替换。
- 标准 Table 固定使用 Ant Design 中号尺寸（`size="middle"`）；表头与表体单元格内边距为上下 `10px`、左右 `16px`，表头字号为 `13px`，单行表头最小高度为 `42px`，背景为 `#F5F4F5`、文字色为 `#606266`；普通长标题仍在列宽内折行并允许表头按内容增高，不得使用省略号截断；多字段表头默认使用 `/` 或 `／` 分隔并保持单行，只有用户明确要求时才在列配置设置 `headerWrap: "wrap"` 折行，未配置或设置 `nowrap` 时保持单行；表头与表体共用 `1px solid #E4E4E7` 外边框，分页不包含在该外边框内。
- `format: "amount"` 的金额列固定使用右对齐。默认单位为“元”，表头自动显示为“字段名(元)”；列配置提供 `unit` 时使用该单位。单位使用英文半角括号且字段名与左括号之间不留空格，单元格不重复显示单位。混合币种列使用 `mixedCurrency: true`，保留原表头并逐行显示币种。
- Table 的列标题和字段值必须完整可见，字段较长时按当前列宽折行；不得以省略号截断业务字段。组合列或其他多字段表头若使用 `/` 连接多个字段，默认保持单行；只有用户明确要求折行时才设置 `headerWrap: "wrap"` 拆成多行。所有相邻表头列之间统一使用颜色 `#D6D6D6`、尺寸 `1px × 16px` 的居中竖向分隔线。操作列与状态 Tag 等紧凑控件可保持单行。

## 表单选择

**EA-TPL-006** 从列表、详情或当前任务内发起，字段少且相互独立、可一次提交完成时，使用 Modal 表单。弹窗内的字段与分组必须服务于明确业务语义，不得为了填充空白创建无业务含义的分组、摘要或装饰模块。复杂联动、长校验、上传、多个业务分区或不可逆提交不能压缩在 Modal 中。

**EA-TPL-007** 新增或编辑任务按可交互信息项数量选择承载方式：不超过 6 项且可在单一连续上下文内完成时使用 Modal；超过 6 项且不超过 12 项时使用 Drawer；超过 12 项时必须使用新标签页中的整页分组表单。复杂联动、上传、长说明或不可逆提交可以在数量未超过阈值时提前升级为 Drawer 或整页表单。只有后续工作依赖前一步完成，或存在上传、解析、复核与提交等明确阶段时，才使用步骤表单。分组表单不得叠加右侧说明配图或第二个主表单；步骤表单不得与 Modal 表单组合。

## 详情、结果与概览选择

**EA-TPL-008** 详情按身份、账户状态、余额口径、关联记录和操作日志分组呈现。金额摘要不得脱离币种、口径和时间范围单独展示；可变更账务的动作必须使用明确操作，不得隐藏在普通文本链接中。结果页必须说明影响对象、金额、币种、业务单号和恢复路径，且不得作为独立业务入口。

**EA-TPL-009** Dashboard 只服务跨记录的业务监控，必须有统一数据范围和口径，并至少包含核心指标、分布或趋势等能够支持判断的视图；不能混入查询结果表格、分页、行操作或批量操作。需要逐条查询、核对或处理记录时，改用查询列表。

## 页面组合约束

**EA-TPL-010** 详情页不得把所有字段渲染成可编辑控件。表单的返回、取消和关闭均需遵循未保存修改确认；辅助浮层不可承载完整步骤流程，也不得替代来源页面本身。

## 能力边界与选择证据

**EA-TPL-011** 当前策略决定哪些页面家族、能力和组合可以生成。`shadow` 页面必须引用同页面族且能力集合匹配的已验证组合；`workflow-only`、`legacy` 或 `pending` 页面不能通过 Page Spec 直接生成，必须报告能力缺口。

**EA-TPL-012** `page-design.md` 和 Page Spec 元数据必须记录已选页面家族、页面方案、能力证据、被排除方案、假设和运行模式。没有策略与验证证据，不得构建或交付。

**EA-TPL-013** “多个业务模块”指表单需要按两个及以上独立业务语义分区，例如业务主体、主体信息、法人信息和结算信息；“信息项”只统计需要用户录入、选择或上传的可交互字段，纯展示说明、模块标题和系统自动回填字段不计入。按照 `EA-TPL-007` 命中整页条件后选择 `form.page`，不得继续使用 Modal 或 Drawer 承载。整页分组表单由内容区顶部的独立返回入口、一个主表单、按业务语义拆分的同级信息模块和一个固定底部操作区组成；不得额外渲染页面标题模块，首个白色业务面直接承载第一个业务模块。信息模块顺序遵循前置选择、主体信息、补充信息和提交确认的任务依赖，不得按控件类型机械分组。

**EA-TPL-014** 内容工作区外层在 Shell 内统一使用 `12px` 内边距；页面内容区的标题、查询、结果和表单分组等直接同级业务模块内边距统一为 `16px`，并统一使用 `8px` 圆角，相邻模块之间的灰色垂直间距固定为 `16px`。模块最后一个字段与业务面底部保持 `16px` 间距，不叠加组件库默认的字段底部外边距。整页分组表单的字段网格统一以 `24px` 行间距组织多行字段，字段项自身的 `margin-bottom` 必须归零，避免单行模块把 `24px` 行间距错误带入模块底部。不得通过额外空白、嵌套卡片或不同圆角制造层级。整页新增表单的操作区必须固定在内容视口底部并在页面滚动时始终可见，横向覆盖内容工作区，使用白色背景，顶部以浅色阴影区分表单内容。操作按钮右对齐，次操作在左、主操作在右，按钮间距为 `8px`；每个按钮宽度按文字、图标和水平内边距自适应，不设置等分宽度，不使用 `flex: 1`，也不得随操作区宽度自动撑满。

**EA-TPL-015** 整页新增表单包含超过 12 个可交互信息项时，各业务信息模块仍按任务顺序纵向排列，但模块内部必须使用标签在上、控件在下的垂直表单布局，不得使用标签在左、控件在右的水平表单布局。普通输入、选择、日期和金额等短字段使用 24 栅格排列：内容工作区宽度不小于 `1200px` 时每项占 `8/24`、每行 3 项；`768px-1199px` 时每项占 `12/24`、每行 2 项；小于 `768px` 时每项占 `24/24`、每行 1 项。控件填满所属栅格列，同行标签基线和控件顶部对齐。地址、上传、长说明、富文本、复杂联动及需要完整帮助或校验信息的字段可按内容需要占 `16/24` 或 `24/24`，不得为了凑满三列压缩可读性；隐藏或条件字段出现、消失后按原字段顺序重新排布，不保留无意义空列。
