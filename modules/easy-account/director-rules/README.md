# 易账通导演规则

## 这套规则解决什么问题

本目录是 Easy Account / 易账通唯一的、面向人阅读的页面设计决策层。它把“页面应该呈现什么样的任务界面、应该选什么页面方案、怎样才算操作正确”分开管理：

1. `01-visual-constitution.md`：每个易账通页面应具备的整体视觉气质。
2. `02-template-application-rules.md`：业务场景应选择哪个页面家族、页面方案和组合。
3. `03-interaction-acceptance-rules.md`：用户如何完成任务，以及如何证明页面正确。

旧 `templates/` 页面模板、`design.md`、`components.md` 和历史 Change 是本目录形成时的输入材料，不是与本目录竞争的规则来源，也不得作为页面生成、修改或评审的运行时输入。

## 设计师维护范围

设计师和产品只维护下面三类长期设计决策：

| 需要改变的内容 | 唯一维护位置 |
| --- | --- |
| 品牌、视觉 Token、密度、组件气质与响应式原则 | `01-visual-constitution.md` |
| 页面家族、选择条件、组合与禁用组合 | `02-template-application-rules.md` |
| 流程、状态、权限、危险确认与验收案例 | `03-interaction-acceptance-rules.md` |

单页字段、样例数据、文案和默认值只写入当前 Change 的 `page-spec.json`。新增设计规则必须添加对应 Rule ID 和验收场景。

`execution/` 下的策略、Schema 和固定渲染器属于研发维护的执行层：它们实现和限制导演规则，但不是设计师需要维护的第四套规则。规则本身不能自动开放未实现的页面能力；需要新能力时，先在三本规则中说明意图和验收，再由研发扩展执行层。

## 权威边界

- 本目录的导演规则是易账通页面设计语义的唯一权威。
- `business-rules.md` 是账户、金额、状态、权限与隐私等业务语义的唯一权威；它不定义视觉或页面方案。
- `execution/generation-policy.json` 是“当前允许生成哪些能力及组合”的唯一权威；它是工程能力清单，不是页面风格或模板规则来源。
- `execution/page-spec.schema.json` 是 Page Spec 结构的参考契约，页面以预览中的实际业务呈现为最终确认依据。
- `../shell/` 是固定框架层，负责导航、多标签、内容工作区、页脚、品牌资产和本地依赖。业务页面只能挂载到其内容插槽，不能重新绘制 Shell。
- 历史 `changes/` 目录只可作为证据和回归样例，不能成为新的规则来源。

## 规则编号

- `EA-VIS-*`：视觉宪法。
- `EA-TPL-*`：模板选择与页面组合。
- `EA-INT-*`：交互、状态与验收。

每一条硬性运行时能力都应至少引用一个 Rule ID。新增硬规则时，先分配 Rule ID，再修改策略或代码。

## 冲突优先级

1. 法律、合规、安全和无障碍要求。
2. 明确的账户金额口径、业务状态、权限和不可逆操作要求。
3. 易账通导演规则。
4. 已选页面方案中更具体的规则。
5. 组件库默认行为。
6. 历史模板、Change 或视觉参考。

低优先级来源不能悄悄覆盖高优先级来源。当前不支持的需求必须输出能力缺口，不能以手写页面绕过策略限制。
