# Easy Account List Context

- Choose `query.basic` for up to six independent query fields; `query.advanced` remains shadow until a golden case proves expansion and dependent filters.
- Use a `12px` outer content inset and two white sibling modules: query conditions and result table. Each module has `16px` inner padding, an `8px` radius and a stable `16px` gap.
- Query actions are right-aligned at `8px` gaps in the final grid column: reset, query, then expand/collapse. The expand/collapse label precedes its icon, which is the rightmost control; its left padding is `8px` and right padding is `0`.
- A result toolbar with category Tabs keeps the Ant Design default Tab height, reserves `8px` above the Tabs and the default `16px` below it (`70px` total), and hides the Tabs navigation gray divider line. A standard title toolbar remains `32px` high.
- When business categories change the query fields or query semantics, render Ant Design Tabs at the top of the query module, above the category-specific fields; keep the result module as a standard titled Table and do not repeat Tabs above it. Only when categories share one query schema may Tabs replace the list title. Switching categories returns pagination to page 1; preserve filters for a shared schema and clear incompatible fields for different schemas.
- Render top-level business Tabs as a full-width navigation band within the business module, using the exact surface color `#FBFCFC` and a `1px solid #E4E4E7` bottom divider; keep the selected label and underline in the brand color.
- Keep the list to two sibling business modules. When a selected account or other primary object owns the overview metrics, place its selector and Ant Design `Statistic` overview inside the query module before the transaction query fields: category Tabs, primary-object selector, overview, then query conditions. Do not render an extra query-condition heading in this combination. If only some query Tabs need that overview, list their unique, declared Tab keys in `summary.config.visibleTabKeys`; omit this property to show the overview on every Tab. A Tab outside this list is an ordinary query list: it renders no overview, management action, overview spacing, or horizontal selector treatment. Only a selector before a visible overview uses a horizontal Form item with the label on the left and the control on the right. On desktop, its total width matches the first Statistic track in the overview instead of using a wider fixed field width; below `768px`, it returns to a full-width vertical item. Ordinary query fields and selectors without a visible account overview remain vertical. Keep no divider between the selector and overview, and reserve exactly `32px` above the overview heading; do not add a gray divider below the overview before the query fields. A query-result aggregate belongs inside the result module. Never render either summary as a third business card.
- A summary may declare `summary.manage` when the current object has a directly related management task. When declared with management configuration, render one `32px` button at the right of the summary heading by default; set `visible: false` only when the product explicitly wants to suppress it. It is Primary by default and becomes secondary only when the Page Spec explicitly sets `primary: false`. Open an Ant Design Modal for up to six configured fields. The Page Spec owns the button label, field definitions, validation, initial values, submit copy and success feedback; the shared runtime must not invent domain-specific rule fields. Do not render this button without the capability and management configuration, or move it into the result Table toolbar. Remove gray divider lines between overview statistics and below the overview; keep the top-level Tabs divider and Table frame where their own rules require them.
- Use a `6px` radius for every standard button and form control across query pages, Modal, Drawer and full-page forms. Keep the `8px` business-module radius, `12px` Modal radius, compact Tag radius and circular icon controls as explicit exceptions.
- Every overview or aggregate metric uses the official Ant Design `Statistic`. Put the semantic label and any fixed unit in `title` with ASCII parentheses and no preceding space (for example, `账户余额(元)`); keep `value` unit-free and do not repeat the unit through `prefix` or `suffix`. Text metrics use the same `title` and `value` contract.
- Table states must cover loading, empty, error and permission-denied. Amount columns align both headers and cells to the right. For a single-currency column, append its unit to the header with ASCII parentheses and no preceding space (default: `金额(元)`), and do not repeat the unit in each cell. Set `unit` for another fixed unit; use `mixedCurrency: true` and show currency per row only when the column genuinely mixes currencies. Every status cell uses an Ant Design Tag with explicit text and a semantic color; never render a Badge, standalone dot or color-only status.
- Render every standard Ant Design Table with `size="middle"` and `10px 16px` padding on header and body cells (`10px` block, `16px` inline). Keep the header exactly `42px` high, with `#F5F4F5` background and `#606266` text. Wrap the header and body together in a `1px solid #E4E4E7` outer border, keep pagination outside that frame, and do not enable a full-cell bordered grid to simulate the outer frame.
- Inline binary role states use `table.switch`: an Ant Design Switch is paired with visible Chinese state text. Role permission selection uses `form.tree`: a checkable Ant Design Tree with an explicit required-field error.
- Every standard Table includes column settings as an icon-only tool with the accessible label “列设置”; it may hide business columns but never the operations column. Confirmed row actions must explain the affected account and resulting state.
- The operations column width follows its visible actions and must not leave excessive trailing blank space.
- The result toolbar title defaults to “查询列表”; a `table.sectionTitle` value is an explicit requirement override. Table headers and cells must show complete labels and values, wrapping within the configured column width instead of truncating with ellipses. Keep only operations and compact status controls on one line when needed.
- Table pagination uses a left/right split: the left side shows the result count (`共 X 条`), and the right side uses Ant Design Pagination with page navigation, a page-size selector, and the available additional-page controls. Changing page size resets to page 1; on narrow screens the two sides stack without overlap.
- `list.modalCreate` may add a compact create Modal when it preserves the list context; `detail.drawer` may open read-only account details when the displayed information has a clear boundary.
