# Easy Account List Context

- Choose `query.basic` for up to six independent query fields; `query.advanced` remains shadow until a golden case proves expansion and dependent filters.
- Use a `12px` outer content inset and two base white sibling modules: query conditions and result table. A query-result `summary` with up to three metrics replaces the result-table title and adds no sibling region. More than three metrics add one unframed row of Statistic cards between the two modules. Query, summary-card row, and result keep a stable `16px` vertical gap; only the two business modules use `16px` inner padding and an `8px` radius.
- Query actions are right-aligned at `8px` gaps in the final grid column: reset, query, then expand/collapse. The expand/collapse label precedes its icon, which is the rightmost control; its left padding is `8px` and right padding is `0`.
- A result toolbar with category Tabs keeps the Ant Design default Tab height, reserves `8px` above the Tabs and the default `16px` below it (`70px` total), and hides the Tabs navigation gray divider line. A standard title toolbar remains `32px` high.
- When business categories change the query fields or query semantics, render Ant Design Tabs at the top of the query module, above the category-specific fields; keep the result module as a standard titled Table and do not repeat Tabs above it. Only when categories share one query schema may Tabs replace the list title. Switching categories returns pagination to page 1; preserve filters for a shared schema and clear incompatible fields for different schemas.
- Render top-level business Tabs as a full-width navigation band within the business module, using the exact surface color `#FBFCFC` and a `1px solid #E4E4E7` bottom divider; keep the selected label and underline in the brand color.
- Separate overview and query-result summary semantics and presentation. An `overview` belongs inside the query module above ordinary query fields: category Tabs, primary-object selector, overview, then query conditions. If only some query Tabs need it, list their unique declared keys in `overview.config.visibleTabKeys`. Only a selector before a visible overview uses a horizontal Form item; on desktop its width matches the first Statistic track, and below `768px` it returns to a full-width vertical item. Keep no divider between the selector and overview, reserve exactly `32px` above the overview heading, add one `1px solid #EDEDED` divider between the overview and the following query conditions, and separate adjacent overview metrics with a centered `1px` wide, `16px` high vertical divider in `#E4E4E7`; hide these vertical dividers when metrics stack into one column. A `summary` aggregates the current query result and must never appear above the ordinary query fields. For one to three metrics, replace the result-table title with `查询汇总：标题 数值 单位｜…` at `14px / 22px`; keep labels and units in the normal text color, values in `#1E75FF`, the full-width `｜` separators in `#E4E4E7`, and preserve the right-side toolbar actions. For more than three metrics, render an unframed row below the query module and above the result Table: individual white Statistic cards with a `12px` gap, `16px` padding, `6px` radius, no border, and no shadow. Do not render a visible summary heading or an outer business surface. When both overview and summary exist, retain their distinct semantics and quantity-based positions.
- An overview may declare `overview.manage` when the current object has a directly related management task. When declared with management configuration, render one `32px` button at the right of the overview heading by default; set `visible: false` only when the product explicitly wants to suppress it. It is Primary by default and becomes secondary only when the Page Spec explicitly sets `primary: false`. Open an Ant Design Modal for up to six configured fields. Do not render this button without the capability and management configuration, and never place it in the query-result summary or Table toolbar.
- Use a `6px` radius for every standard button and form control across query pages, Modal, Drawer and full-page forms. Keep the `8px` business-module radius, `12px` Modal radius, compact Tag radius and circular icon controls as explicit exceptions.
- Every overview metric and every query-result summary with more than three metrics uses the official Ant Design `Statistic`. Put the semantic label and any fixed unit in `title` with ASCII parentheses and no preceding space (for example, `账户余额(元)`); keep `value` unit-free and do not repeat the unit through `prefix` or `suffix`. Text metrics use the same `title` and `value` contract. The one-to-three-metric inline summary is the only exception and follows the compact toolbar format above.
- Table states must cover loading, empty, error and permission-denied. Amount columns align both headers and cells to the right. For a single-currency column, append its unit to the header with ASCII parentheses and no preceding space (default: `金额(元)`), and do not repeat the unit in each cell. Set `unit` for another fixed unit; use `mixedCurrency: true` and show currency per row only when the column genuinely mixes currencies. Every status cell uses an Ant Design Tag with explicit text and a semantic color; never render a Badge, standalone dot or color-only status.
- Render every standard Ant Design Table with `size="middle"` and `10px 16px` padding on header and body cells (`10px` block, `16px` inline). Keep a single-line header at `42px` minimum height, with `13px` text, `#F5F4F5` background and `#606266` text; header titles and body values must wrap within their configured column width instead of truncating. Multi-line headers may grow vertically to fit their content. Wrap the header and body together in a `1px solid #E4E4E7` outer border, keep pagination outside that frame, and do not enable a full-cell bordered grid to simulate the outer frame.
- Inline binary role states use `table.switch`: an Ant Design Switch is paired with visible Chinese state text. Role permission selection uses `form.tree`: a checkable Ant Design Tree with an explicit required-field error.
- Every standard Table includes column settings as an icon-only tool with the accessible label “列设置”; it may hide business columns but never the operations column. Confirmed row actions must explain the affected account and resulting state.
- The operations column width follows its visible actions and must not leave excessive trailing blank space.
- The result toolbar title defaults to “查询列表”; a `table.sectionTitle` value is an explicit requirement override. Table headers and cells must show complete labels and values, wrapping within the configured column width instead of truncating with ellipses. Multi-field headers separated by `/` or `／` stay on one line by default; only an explicit column-level `headerWrap: "wrap"` requirement splits the fields into separate header lines. `headerWrap` accepts `wrap` or `nowrap` (`nowrap` is the default). Every adjacent table-header column pair uses a centered `1px` wide, `16px` high divider in `#D6D6D6` within the header. Keep only operations and compact status controls on one line when needed.
- Table pagination uses a left/right split: the left side shows the result count (`共 X 条`), and the right side uses Ant Design Pagination with page navigation, a page-size selector, and the available additional-page controls. Changing page size resets to page 1; on narrow screens the two sides stack without overlap.
- `list.modalCreate` may add a compact create Modal when it preserves the list context; `detail.drawer` may open read-only account details when the displayed information has a clear boundary.
